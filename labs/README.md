# قرارات السيادة والبنية التحتية والاعتماد على الموردين · المختبرات

ثلاثة مختبرات لمقرر أكاديمية سدايا **LDS-EXE-208**، بالترتيب الذي يذكره المقرر: توزيع عشرة أحمال عمل بحسب فئة البيانات، ثم مجموعة مهام واحدة ثنائية اللغة على نموذج مستضاف ونموذج محلي، ثم تمرين الانسحاب. كل مختبر صفحة إرشادية بالعربية: الهدف، والملفات، والخطوات بدقائقها، وأسئلة تحقق، ومهمة إضافية ✱، وملاحظات للمدرّب.

كل المختبرات في جهة واحدة: **أمانة مدينة الكَثيب**، جهة حكومية بلدية افتراضية في مدينة افتراضية، ومزوّد نماذج أجنبي مخترع اسمه «أورفينا». كل الأسماء والأرقام والأحداث مخترعة، وكل الملفات اصطناعية ومصنفة «عام». العناصر العشرون في `files/items.csv` كتبها المقرر من نصوص منشورة افتراضية، ولا شيء غيرها يُرسل إلى أي نموذج.

## ما يحتاجه المشارك

- جدول بيانات (LibreOffice Calc أو Microsoft Excel).
- للمختبرين 1.2 و1.3: صورة الحاسوب المحمول التي يجهزها المدرب، وفيها `uv` وأداة تشغيل محلية لنموذج مفتوح الأوزان (Ollama أو llama.cpp) ونموذج محمّل مسبقًا يدعم العربية؛ ونموذج مغلق مستضاف بواجهة محادثة متوافقة مع OpenAI في فئة تجريبية، بمفتاح في متغير البيئة `HOSTED_API_KEY`. لا يُنزَّل شيء أثناء المختبر.
- من لا يملك الصورة أو المفتاح يضيف `--standin` إلى الأوامر: تشغيل بديل كتب المقرر إجاباته وأزمنته بسيناريو، لا مخرجات نموذج، ويكتب ذلك في كل سطر من السجل.

## البرامج

برامج Python بمكتبتها القياسية وحدها، كل منها ملف واحد يُشغَّل بـ`uv run` من جذر المستودع:

```
uv run labs/harness/compare.py [--standin] [--only hosted|local]
uv run labs/harness/drill.py --scenario S1|S2|S3|S4 [--standin]
uv run labs/harness/verify_log.py labs/harness/runs/<run id>/log.jsonl
```

تُحفظ التشغيلات في `labs/harness/runs/`، وإعداد المشارك في `labs/harness/config.json`؛ وكلاهما لا يُرفع إلى المستودع. السجل لا يحفظ المفتاح ولا مسارًا على الجهاز.

## للمدرّب

- **قبل اليوم:** جهّز صورة الحاسوب: ثبّت `uv` وأداة التشغيل المحلية، ونزّل نموذجًا مفتوح الأوزان يدعم العربية بترخيص يسمح بالاستعمال (مثال: ALLaM-7B-Instruct-preview بترخيص Apache-2.0، أو غيره)، وشغّل `uv run labs/harness/compare.py --only local` مرة على الصورة. العنوان الافتراضي في الإعداد `http://127.0.0.1:11434/v1` (Ollama)؛ وأداة llama.cpp تطبع عنوانها عند التشغيل.
- `solutions/answer_key.md`: ما زُرع في الملفات، وأين، وأي مختبر يكشفه.
- `solutions/key.json`: الأرقام المرجعية للتشغيل البديل.
- `uv run labs/solutions/check_all.py`: يتحقق أن المولّد يكتب الملفات نفسها، وأن مفتاح التوزيع يستعمل رموز الخطة وحدها، وأن التشغيل البديل للمختبرين 1.2 و1.3 يعطي الأرقام المرجعية، وأن نقطة البداية (دون إعداد ودون سجل) تنتهي برسالة لا بخطأ برمجي. ومع `--placement <ملف>` يقدّر جدول توزيع مشارك من 50.
- `uv run labs/_tools/make_files.py` يكتب ملفات الحالة من جديد (`--check` يقارن فقط).

لم يُشغَّل أي نموذج حقيقي في بناء المقرر: المختبران 1.2 و1.3 شُغّلا بالتشغيل البديل وبخادم تجريبي محلي يحاكي واجهة المحادثة.
